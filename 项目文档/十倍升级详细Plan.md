# 十倍升级详细 Plan

> 项目：Global Health Spending · R 大作业  
> 当前基线：v4.1，高标准审计修复后版本  
> 目标：把现有“可提交、可部署、可展示”的分析项目升级为“数据新闻 + 交互产品 + 可复现研究系统”的完整作品。

---

## 0. 当前基线与升级口径

### 0.1 当前基线

| 维度 | 当前状态 |
|---|---:|
| 内容章节 | 36 个内容章节 |
| 核心发现 | 14 项 findings |
| 主体静态图 | 50 张左右 |
| 独立交互组件 | 24 个 HTML widget |
| Shiny 模块 | 12 个模块化页面 |
| 自动部署 | GitHub Pages + shinylive + shinyapps.io workflow |
| 审计状态 | 空白图修复、Shiny CI 修复、文档已同步 |

### 0.2 “十倍升级”的定义

这里的十倍不是简单把文件数量堆到十倍，而是从 7 个方向同时提升：

| 方向 | 当前短板 | 十倍升级目标 |
|---|---|---|
| 数据扩展 | GHED + 部分 WDI 为主 | 建立多源 country-year feature mart |
| 因果识别 | 以描述、相关、面板 FE 为主 | 增加事件研究、合成控制、DID、稳健性检查 |
| 预测升级 | 单变量 ARIMA 为主 | 升级为 panel forecasting、层级模型、情景扇形图 |
| 公平性升级 | 国家间不平等为主 | 增加国内 OOP 灾难性支出和双层公平框架 |
| 交互升级 | widget 已多但联动有限 | 增加 Shiny 图表联动、下载、状态保存、国家对比篮子 |
| 设计升级 | 已有统一卡片和夜色模式 | 增加多版式叙事、scroll-spy、图注系统、方法故事页 |
| 工程升级 | 有构建和部署 | 增加自动截图、链接、PNG 空白、CI artifact 体积测试 |

### 0.3 总宗旨

十倍升级必须同时服务于五个目标，而不是只追求数量：

| 宗旨 | 具体含义 | 不合格表现 |
|---|---|---|
| 美观性 | 视觉统一、层级清晰、配色克制、留白合理、暗色模式完整 | 图表拥挤、颜色随意、字体不统一、卡片阴影和圆角不一致 |
| 多样性 | 图表类型、叙事结构、交互方式、统计方法和国家案例都要丰富 | 全部都是折线图/柱状图，章节形式重复，读者审美疲劳 |
| 阐述丰富全面性 | 每个结论都要有问题、方法、证据、解释、局限和政策含义 | 只有图没有解释，或只有口号式结论没有数据支撑 |
| 科学性 | 变量口径清楚，模型假设明确，因果表述谨慎，预测有回测 | 把相关说成因果，不写数据缺失，不说明单位和方法 |
| 正确性 | 数值、单位、年份、国家、代码、链接、部署结果都可复核 | 图文数字不一致，README 命令失效，widget 打不开 |
| 无 AI 痕迹 | 文风自然、具体、有项目细节，不出现模板化 AI 套话 | 出现“作为 AI”“本文旨在深入探讨”等泛化语句或空洞总结 |
| 可复现性 | 从原始数据到最终 HTML 都有命令、缓存、日志和版本说明 | 只能在某台电脑运行，缺包、缺数据、缺 secret 即失败 |
| 可维护性 | 文件职责清楚，新增图/模型/widget 有固定入口和命名规则 | 所有逻辑堆在一个脚本里，函数命名混乱，难以扩展 |

### 0.4 硬性红线

以下问题一旦出现，必须先修复，不能继续堆新内容：

| 红线 | 说明 |
|---|---|
| 空白图 | PNG/SVG/HTML 中出现只有标题、坐标、占位文字或白屏的图 |
| 假结论 | 结论无法由图表、表格或模型支撑 |
| 伪因果 | 没有识别设计时使用“导致、证明、显著改善”等因果表达 |
| 伪数据 | 使用未说明来源、无法复现、手工硬编的核心数据 |
| secret 泄露 | token、secret、`.Renviron`、账号凭据写入源码、文档或提交历史新增内容 |
| AI 痕迹 | 出现 AI 自称、模板化泛泛段落、重复口号、明显机器翻译腔 |
| 链接损坏 | README、静态页、widget、Shiny、Pages 任一核心入口打不开 |
| 文档过期 | README、Rmd、部署文档与真实文件数量、命令、目录结构不一致 |
| 过度装饰 | 为了炫技牺牲可读性，动画、阴影、渐变影响信息判断 |
| 不可复现 | 新功能不能通过 `Rscript 构建.R ...` 或明确命令重建 |

### 0.5 验收口径

每一轮升级都必须回答四个问题：

| 问题 | 最低要求 |
|---|---|
| 这个新增内容解决了什么研究问题？ | 明确写在章节标题、finding 或图注中 |
| 使用了什么数据和方法？ | 标明数据源、变量、年份、样本、方法和局限 |
| 读者能否看懂并复核？ | 图表有单位、解释、代码入口和复现命令 |
| 是否破坏已有提交版？ | 构建、链接、空白图、widget、Shiny、README 全部复核 |

| 指标 | 当前 | 十倍升级目标 | 验收标准 |

### P1 · 多源数据 Feature Mart

| 项 | 内容 |
|---|---|
| 目标 | 把 GHED、WDI、WHO GHO、IMF、OECD、GBD 等整合成统一 country-year 面板 |

| 产物 | `派生数据/处理结果/feature_mart.rds`、`派生数据/处理结果/feature_dictionary.csv` |

| 风险 | 外部 API 失败、口径不一致、缓存过大 |
| 缓解 | 优先读缓存；API 失败时降级；大文件不提交，提交压缩摘要 |

## 5. 全面细致验收标准

本章是十倍升级的核心执行规范。所有新增图表、章节、交互、网页、README、部署文档和最终提交产物都必须按这些条款验收。

### 5.1 图表美观性标准

| 检查项 | 必须做到 | 禁止出现 |
|---|---|---|
| 视觉层级 | 标题、副标题、坐标、图例、注释、来源层级清楚 | 标题过长、坐标拥挤、图例遮挡数据 |
| 配色 | 使用统一项目色板；同一含义固定颜色；色盲友好 | 同一指标在不同图中颜色反复变化 |
| 字体 | 中文、英文、数字统一；字号适配 PNG 和 HTML | 字体缺失、中文乱码、导出后文字过小 |
| 留白 | 图内边距和标签避让合理；重要标注不贴边 | 图形元素挤满画布，标签重叠不可读 |
| 背景 | 白底/浅色图清爽，暗色模式下对比度足够 | 灰底过重、网格线抢夺注意力 |
| 注释 | 只标关键国家/年份/异常点；注释解释“为什么重要” | 到处贴标签，或只贴国家名没有解释 |
| 图例 | 图例顺序符合逻辑；中英标签准确 | 图例名是变量名如 `gghed_che` 且无解释 |
| 移动端 | 小屏下仍能看清主体趋势和图注 | 大表格和宽图在手机端横向溢出严重 |

### 5.2 图表多样性标准

图表类型必须服务于研究问题，不能为了多样而乱用。十倍升级后至少覆盖以下图表家族：

| 图表家族 | 适用问题 | 推荐用法 |
|---|---|---|
| 趋势图 | 长期演化、疫情冲击、政策前后变化 | line、area、indexed line、small multiples |
| 分布图 | 国家差异、收入组差异、离群点 | violin、ridge、boxplot、beeswarm、histogram |
| 关系图 | 支出与健康结果、GDP 与 CHE、OOP 与 UHC | scatter、bubble、hexbin、partial residual |
| 地图 | 空间差异、区域聚集、外援依赖 | choropleth、bivariate map、cartogram |
| 组成图 | 政府、私人、外援、用途结构 | stacked area、100% bar、waffle、ternary |
| 排名图 | Top/Bottom、排名变化、国家对比 | lollipop、bump chart、slopegraph |
| 不平等图 | Gini、Theil、Lorenz、集中曲线 | Lorenz curve、decomposition bar |
| 模型图 | 回归结果、系数、置信区间 | coefficient plot、marginal effects |
| 预测图 | 2030 情景、回测、不确定性 | fan chart、forecast ribbon、scenario waterfall |
| 网络图 | 国家相似性、资金流、聚类结构 | network、sankey、alluvial |
| 质量图 | 缺失、异常、覆盖率、数据版本 | missingness heatmap、coverage matrix |
| 方法图 | 识别设计、样本筛选、数据管线 | flowchart、DAG、pipeline diagram |

最低比例要求：

| 类型 | 最低数量 |
|---|---:|
| 趋势 / 分布 / 关系 / 地图 / 组成 / 排名 | 每类至少 10 张 |
| 模型 / 预测 / 不平等 / 质量 / 方法图 | 每类至少 5 张 |
| 交互版图表 | 至少 60 个可打开视图或模块视图 |

### 5.3 图表科学性与正确性标准

| 检查项 | 必须做到 |
|---|---|
| 数据源 | 每张主图必须能追溯到 GHED、WDI、GHO、IMF、OECD、GBD 或明确缓存 |
| 样本 | 写明国家数、年份范围、是否剔除缺失或异常 |
| 单位 | 货币写清 USD/current/constant/2023，比例写清百分比还是 0–1 |
| 变换 | log、标准化、z-score、winsorize、deflate 都要说明 |
| 加权 | 人口加权、GDP 加权、简单平均必须明确区分 |
| 不确定性 | 回归、预测、估计指标尽量提供置信区间或敏感性结果 |
| 因果措辞 | 只有在 DID、事件研究、合成控制等设计充分时才使用因果语言 |
| 预测措辞 | 预测必须写明“不是确定预言”，并提供回测误差 |
| 异常点 | 关键异常国家需要解释，不应悄悄删除 |
| 复核 | 图中关键数字必须能在表格、模型输出或代码中复现 |

### 5.4 图表内容模板

每张主图应具备以下信息：

| 元素 | 标准 |
|---|---|
| 标题 | 回答“这张图说明什么”，避免只写变量名 |
| 副标题 | 写样本、年份、口径或方法 |
| 坐标轴 | 单位完整；百分比和美元不能混淆 |
| 图例 | 中英或清晰中文标签；顺序有意义 |
| 图注 | 80–150 字，包含发现、解释、局限 |
| 来源 | GHED/WDI/GHO 等来源 + 项目处理 |
| 代码入口 | 能定位到 `程序/*.R` 中的生成函数 |
| fallback | 缺包、缺数据、地图下载失败时不白屏 |

### 5.5 阐述内容丰富全面性标准

每个核心 finding 必须从“观察”升级为“论证”。建议结构如下：

| 组成 | 要求 |
|---|---|
| 研究问题 | 用一句具体问题开头，不写空泛主题 |
| 背景动机 | 说明为什么这个问题重要，和卫生筹资/公平/政策有关 |
| 数据口径 | 写清数据源、年份、变量、样本、缺失处理 |
| 方法说明 | 用读者能懂的语言解释统计方法和选择理由 |
| 核心发现 | 用 2–4 个具体数字或方向描述结果 |
| 图表解读 | 指出图中最关键的视觉证据 |
| 稳健性 | 写明是否换指标、换样本、换年份仍成立 |
| 局限 | 明确说明不能回答什么、可能有哪些偏差 |
| 政策含义 | 指出政策对象、干预路径、风险误读 |
| 下一步 | 指向可继续分析的数据或模型 |

篇幅要求：

| 内容类型 | 建议篇幅 |
|---|---:|
| 单张主图图注 | 80–150 字 |
| finding 主解释 | 400–800 字 |
| 方法专题 | 800–1500 字 |
| 国家画像 | 每国 300–600 字 |
| 模型局限说明 | 每类模型 150–300 字 |

### 5.6 无 AI 注释痕迹标准

文本必须像一个真实项目作者写出的研究说明，而不是通用生成文本。

| 类型 | 禁止 | 应改为 |
|---|---|---|
| AI 自称 | “作为 AI”“我无法”“根据你的要求” | 直接写项目事实和执行标准 |
| 空泛套话 | “本文旨在深入探讨复杂关系” | “本节比较 2000–2023 年政府筹资占比与 OOP 变化” |
| 过度形容 | “极其显著、巨大提升、革命性变化” | 用具体数值、区间和样本说明 |
| 无来源判断 | “显然”“众所周知”“可以看出” | “在 2022 年样本中，X 组中位数高于 Y 组” |
| 机械并列 | 连续多段同样句式和同样结尾 | 每段围绕具体证据写不同功能 |
| 假引用 | 编造论文、链接、数据库版本 | 只引用真实数据源和真实文献 |
| 占位内容 | “待补充”“这里插入图表”“TODO” | 未完成内容不得进入最终提交版 |
| 机器翻译腔 | 生硬直译英文概念 | 用自然中文解释，必要时括注英文术语 |

人工复核要求：

| 检查项 | 方法 |
|---|---|
| 读 aloud | 连续读 3 段，如像模板或口号，必须重写 |
| 数字锚定 | 每个重要判断至少对应一个数字、图或模型 |
| 项目细节 | 每段尽量包含年份、国家、指标、方法或文件入口之一 |
| 删除套话 | 删除不增加信息量的“重要意义、深入分析、综合探讨”等空词 |

### 5.7 静态网页要求

| 模块 | 细致要求 |
|---|---|
| Hero | 明确项目主题、数据范围、核心产物、在线入口；视觉上有冲击但不遮挡信息 |
| 导航 | sticky 或清晰目录；章节锚点稳定；移动端可折叠 |
| Snapshot | KPI 卡片必须有单位、年份、解释，不只放数字 |
| Data & Methods | 展示真实代码片段、数据管线、变量字典和局限 |
| Findings | 每项都有研究问题、方法、图、表、解释、局限、政策含义 |
| Gallery | 支持主题筛选；每图有缩略图、图注、来源、代码入口 |
| Widgets | iframe 懒加载；有打开新窗口链接；本地路径和线上路径都有效 |
| Reproducibility | 命令可复制；说明预期输出；写明常见失败原因 |
| Conclusion | 结论必须回扣证据，不写空泛政策口号 |
| Footer | 写清作者、数据源、生成时间、版本、仓库和部署链接 |

静态网页美观标准：

| 维度 | 标准 |
|---|---|
| 版式节奏 | 大章节之间有呼吸感，小卡片之间间距一致 |
| 色彩 | 主色、强调色、中性色固定；地图和类别色板不冲突 |
| 暗色模式 | 所有卡片、表格、iframe 容器、代码块、图注都能正常反色 |
| 表格 | 表头固定或清晰；数字右对齐；关键列高亮 |
| 代码块 | 只展示必要片段；有复制体验；不出现无解释长代码 |
| 视觉焦点 | 每屏只有 1–2 个主要焦点，避免信息噪音 |
| 响应式 | 1366px、1024px、768px、390px 至少四档可读 |

## 8. 最终 Definition of Done

项目达到十倍升级完成状态时，应同时满足：

- **数据**：多源 feature mart 可构建，变量字典完整。
- **分析**：40–60 个研究问题，每个有图、表/模型、解释、局限。
- **可视化**：120+ 张静态图，全部通过空白检测。
- **交互**：60+ widget 或 Shiny 交互视图，均有 loading/error/empty 状态。
- **Shiny**：18+ 模块，支持国家篮子、下载、状态保存和政策模拟。
- **叙事**：静态首页具备多版式数据新闻结构，每图有图注。
- **美观**：全站使用统一色板、字体、卡片、图注、暗色模式和响应式规则。
- **多样**：图表类型、模型类型、国家案例、章节版式和交互方式均有明显差异化。
- **丰富**：每个核心结论都有背景、数据、方法、证据、解释、局限、政策含义。
- **科学**：所有变量、单位、样本、方法、假设、局限和不确定性都清楚写明。
- **正确**：README 数字、HTML 统计、图表结果、模型表和构建产物保持一致。
- **工程**：CI 自动检测 parse、构建、空白图、坏链接、widget 错误、secret。
- **部署**：GitHub Pages 稳定；shinyapps.io secrets 存在时自动部署。
- **文档**：README、部署手册、方法手册、开发手册齐全。
- **安全**：无 token/secret 出现在源码、文档、workflow 和提交历史新增内容中。
- **无 AI 痕迹**：最终页面和文档没有 AI 自称、模板腔、占位语、虚假引用和空泛套话。
