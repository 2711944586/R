# 🌐 部署教程 · shinylive · 把 Shiny 搬进浏览器

> **核心价值**：用 [shinylive](https://posit-dev.github.io/r-shinylive/) 把 Shiny app 编译成 **WebAssembly**，
> 部署到 GitHub Pages 即可，**完全零服务器、零本地运行**，用户打开就能交互。
> 这是满足用户"直接打开观看"需求的**最佳路径**。

---

## 一、工作原理

```
Shiny app (仪表盘/)
     ↓
shinylive::export("仪表盘", "网站发布/仪表盘")
     ↓
生成 HTML + WebR WASM bundle (~40-80 MB 静态资产)
     ↓
放在 GitHub Pages 的 网站发布/仪表盘/
     ↓
用户打开 https://<user>.github.io/<repo>/仪表盘/
     → 浏览器下载 WebR runtime + 所有 R 包 + app 源码
     → 在用户浏览器里起一个 WebAssembly R 会话
     → 直接跑 Shiny，无任何服务器调用
```

**限制**：
- 首次打开较慢（30 秒 – 1 分钟下载 40 MB）之后缓存。
- 不是所有 R 包都支持 WebR — `fixest` / `sf` / `prophet` 目前**不支持**。
- 本项目已在 `仪表盘/` 里做了兼容：用 `fit_panel_fe` 就走服务端版，走 shinylive 时自动降级到 `stats::lm()`。

## 二、本地一次性编译

### 2.1 装 shinylive（R 包）

```r
install.packages("shinylive")
# 或开发版
remotes::install_github("posit-dev/r-shinylive")
```

### 2.2 导出

```r
shinylive::export(
  appdir = "仪表盘",        # 你的 Shiny app 目录
  destdir = "网站发布/仪表盘",  # 输出目录（会被 Pages 服务）
  quiet = FALSE
)
```

**产物**：`网站发布/仪表盘/` 下约 **40-80 MB**，包含：

```
网站发布/仪表盘/
├── index.html              主入口
├── edit/index.html         编辑器版（可选）
├── shinylive/              WebR + Shiny runtime
│   ├── webr/               WebAssembly R (~15 MB)
│   ├── shiny/              Shiny JS runtime
│   └── pyodide/            (若有 Python)
└── app.json                app 清单
```

### 2.3 本地预览

```r
# 启动一个小服务预览
shinylive::run_app("网站发布/仪表盘")
# 或自己用 Python 起静态服务
# python3 -m http.server -d 网站发布 8000
```

打开 <http://localhost:8000/仪表盘/>。

## 三、自动化：嵌入 deploy.yml

本项目 `.github/workflows/deploy.yml` 已集成 shinylive 编译到 `build` job：

```yaml
- name: Build shinylive app → 网站发布/仪表盘/
  run: |
    Rscript -e '
    if (!requireNamespace("shinylive", quietly=TRUE)) install.packages("shinylive")
    shinylive::export("仪表盘", "网站发布/仪表盘", quiet=FALSE)'
```

**push 到 main 即触发**：

```bash
git push origin main
```

Pages 会同时发布：
- `/` — Quarto Book
- `/仪表盘/` — shinylive Shiny

## 四、让 Shiny app 对 WASM 友好

### 4.1 禁用不兼容包

在 `仪表盘/global.R` 顶部：

```r
.webr <- isTRUE(Sys.getenv("SHINYLIVE") == "1") ||
         requireNamespace("webr", quietly = TRUE)

if (!.webr) {
  library(fixest)   # 服务端才用
}
```

然后 `仪表盘/server.R` 里：

```r
if (.webr) {
  fit <- stats::lm(log_che ~ log_gdp, data = d)   # fallback
} else {
  fit <- fixest::feols(...)
}
```

### 4.2 预先烘焙数据

**WASM 里跑 WB API 会被浏览器 CORS 挡**。所以：

1. 本地跑 `targets::tar_make()` 生成 `派生数据/处理结果/master_enriched.rds`。
2. `shinylive::export` 会自动把 `仪表盘/` 下的所有文件打包 → **把 master RDS 复制到 `仪表盘/数据快照/`**：

```r
# 构建.R 里会做这一步
file.copy("派生数据/处理结果/master_enriched.rds",
          "仪表盘/数据快照/snapshot.rds", overwrite = TRUE)
```

然后 `仪表盘/global.R`：

```r
master <- readRDS("数据快照/snapshot.rds")  # 注意相对路径！
```

### 4.3 包体积控制

shinylive 会自动分析 `library()` 调用。每多一个包 +3-10 MB。**紧裁**：

- ✅ `shiny`, `bslib`, `dplyr`, `tidyr`, `ggplot2`, `scales`, `plotly`
- ✅ `leaflet`（大但值），`DT`（大但值）
- ❌ `fixest`, `prophet`, `sf`, `rnaturalearth`（WASM 不支持或太大）
- ❌ `reactable`（大，用 `DT` 替代）

## 五、嵌入 Quarto Book 章节

shinylive 还可**直接嵌入 Quarto 页面**（不需要独立部署）。

### 5.1 装 Quarto 扩展

```bash
quarto add quarto-ext/shinylive
```

### 5.2 在章节里嵌入

```markdown
---
filters:
  - shinylive
---

```{shinylive-r}
#| standalone: true
#| viewerHeight: 600

library(shiny)
library(dplyr)
# ... 你的 app ...
```
```

渲染后 Quarto 会把 shinylive runtime 自动加载进该页面，读者可直接在文章里操作。

## 六、性能 / 体验优化

### 6.1 预热 WebR runtime

首次启动会下载 15 MB WebR。加一段 JS 预下载：

```html
<!-- 在 网站发布/index.html 头部 -->
<link rel="preload" href="/仪表盘/shinylive/webr/webr_core.wasm"
      as="fetch" crossorigin="anonymous">
```

### 6.2 Loading splash

Shiny 首次启动有 ~20 秒黑屏。在 `仪表盘/数据快照/` 放一张 loading 图：

```r
# 仪表盘/ui.R
tags$head(
  tags$link(rel = "stylesheet", href = "app.css"),
  tags$style(HTML(
    ".shiny-loader {
       position: fixed; inset: 0; background: #FAF7F2;
       display: grid; place-items: center;
     }"
  ))
)
```

### 6.3 缓存策略

Pages 默认对 `.wasm` / `.data` 都设了 1 年缓存。再访问时几乎瞬开。

## 八、常见问题

### ❌ WASM 下载 404

- 确认 `网站发布/仪表盘/shinylive/` 有内容（本地 `ls 网站发布/仪表盘/shinylive`）。
- GitHub Pages 默认允许 `.wasm`，但**不服务 `_files` 开头目录** → shinylive 不用这种命名，无需担心。

### ❌ `Error in loadNamespace: "fixest"`

包不兼容 WASM。按 §4.1 做 fallback。

### ❌ App 启动很慢

正常。首次 40-60s。二次 5s。考虑给用户看一个 progress spinner。

### ❌ `export()` 报错 "app too large"

shinylive 默认上限 400 MB（太多依赖）。裁包 §4.3。或者用 `shinylive::export(..., assets_version = "0.10.0")` 指定更轻的 runtime。

### ❌ `arrow` / `parquet` 文件读不了

WASM 里 `arrow` 包不稳定。换用 `readRDS` + RDS 格式（参考 §4.2）。
